### API 调用方式探索

1. **流式调用（streaming=True）**：火山 gateway 在最后一个 chunk 不返回 `usage_metadata`，导致无法统计 token 用量。
2. **非流式调用（streaming=False）**：`usage_metadata` 正常返回，包含 `input_tokens`、`output_tokens`、`total_tokens`、`output_token_details.reasoning`。
3. **最终选择**：使用非流式调用，确保能完整采集 token 数据。

#### 并发策略

- 初始版本为串行执行，143 次评测预计 6+ 小时（每次调用约 160s）。
- 改为 `ThreadPoolExecutor(max_workers=3)` 并行，预计 ~127 分钟。
- 实际运行约 2 小时 12 分钟完成全部 143 次评测。
- 中间结果每批保存一次 JSON，防止意外中断丢失数据。

#### 关键发现

1. **综合最佳**：`doubao-seed-2.0-lite` — 评分 82.1，语法通过率 92%，速度快（55s/call），各维度均衡无短板。
2. **速度之王**：`deepseek-v4-flash` — 平均 35s/call，最快的模型，且评分 74.4 排第三。
3. **算法之王**：`kimi-k2.6` 和 `kimi-k2.7-code` — 算法维度得分最高（91-93），但 Kimi 系列超时严重（各 3 次 API 超时），稳定性差。
4. **系统设计最强**：`deepseek-v4-pro` — 系统设计 89 分，项目生成 89 分，适合架构级任务。
5. **重构最强**：`kimi-k2.7-code`（93 分）和 `doubao-seed-2.0-code`（92 分）。
6. **代码理解最强**：`doubao-seed-2.0-pro` 和 `doubao-seed-2.0-mini`（91 分）。
7. **稳定性问题**：Kimi 系列（k2.6 和 k2.7-code）各有 3 次超时失败（5 分钟超时限制）。
8. **doubao-seed-2.0-code 和 pro 语法通过率低**（38%）— 大量 reasoning tokens（7800-8700），但实际代码语法错误率高。
9. **minimax-m3 表现最弱**（49.3 分）— 系统设计和健壮性维度得分极低（25 分）。
