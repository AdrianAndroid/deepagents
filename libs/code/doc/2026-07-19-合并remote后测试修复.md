## 轮次 1 - 定位并修复 `test_messages.py` 中 11 个 `TestToolCallMessageExpandHint` / `TestToolCallMessageEmptyResult` 失败

### 用户提问要点
上一轮 merge origin/learn 后，全量 `pytest tests/unit_tests -q -n auto` 有 2 个失败（后经完整跑一遍实为 11 个）。需要定位根因并修复，最终目标：跑全绿 + 提交 + push。

### 结论

11 个失败的根因不是 merge 冲突残留，而是**远端两个连续 commit 之间自身就存在不一致**：

| commit | 类别 | 内容 |
|---|---|---|
| `8f1e25e40` "解决折叠问题-不通" | 代码 + 测试 | `set_success` 里把 `read_file`/`grep`/`glob`/`edit_file` 都改成 success 时 `self._expanded = True`；同步改了 265 行测试断言，要求 "auto-expand on success" |
| `aa089113a` "纠正工具" | 只改代码 | 把 `set_success` 回退：**只有 `edit_file`** 依然 auto-expand，`read_file`/`grep`/`glob` 又恢复 collapse-by-default。**但没有同步回退 test_messages.py** |

merge 完之后 `messages.py` 是 `aa089113a` 的行为（只 edit_file auto-expand），`test_messages.py` 是 `8f1e25e40` 的期望（四个工具都 auto-expand），互相冲突 → 11 个失败。

### 关键操作 / 文件改动

1. **导出 `8f1e25e40` 对测试文件的 diff** → `/tmp/8f_tests.patch`（477 行）
2. **反向应用整个 patch**：`git apply -R /tmp/8f_tests.patch`（clean，无冲突）
3. 反向应用后 `edit_file` 测试也回到 "collapse by default" 期望，但 `messages.py` 现在 edit_file 是 auto-expand，所以 `test_edit_file_success_expands_to_original_output` 会失败。**只手工重写这一个 case**，改回 auto-expand 期望（`_expanded is True`、`_full_row.display is True`、toggle 后 collapse）
4. **顺手清理** `libs/code/deepagents_code/tui/textual_adapter.py` 中 `-X theirs` merge 后残留的 4 处 `turn_exit_reason["reason"] = ...` 赋值 + 1 处 `except Exception as turn_exc:` 分支（这些在上一轮已删除变量定义，只剩下引用会 NameError）

### 关键结论 / 复用要点

- `messages.py::ToolCallMessage.set_success` 当前策略（自 `aa089113a` 起）：
  - **只有** `edit_file` 会强制 `self._expanded = True`（`_is_search_no_result_output` 结果除外）
  - `read_file`/`grep`/`glob` 都走 `_COLLAPSE_OUTPUT_BY_DEFAULT` 分支，默认折叠 body，只显示 expand hint
- 以后如果再想让 `read_file`/`grep`/`glob` auto-expand，改 `set_success` 判断条件时**必须同步**修改 `test_messages.py` 里对应的 11 个测试断言
- Merge 有相邻两个 commit 反复改同一个 API 的行为时，`-X theirs` 会拿到最后一个 commit 的代码，但要检查夹在中间的测试是否也被后续 commit 回退
