# 每轮问答后在屏幕上打印模型响应元数据

## 轮次 3 - 去厂商绑定:删除路由别名启发式,改为纯数据驱动

### 用户提问要点

- 不想局限于火山引擎 `ark-code-latest`,以后可能换其他厂商的 coding plan,甚至接入自己的模型。
- 当前 `_looks_like_routing_alias` / `_ROUTED_SEGMENTS` / `_ROUTED_MODEL_SENTINELS` 是基于火山命名约定的硬编码启发式,换厂商就失效。

### 结论 / 方案

**去掉猜测,只展示事实。** 删除所有厂商特定的路由别名检测逻辑,只依据两个字段做展示:

- **requested** — 用户配的模型名(`ls_model_name`)
- **served** — 响应回显的模型名(`response_metadata.model_name`)

显示规则:

| 情况 | 显示 |
|------|------|
| 两者相同 / 只有其一 | 显示那个名字 |
| served 为 sentinel(`"auto"` / `"none"` / `"null"` / `""`) | 只显示 requested |
| 两者不同 | `requested->served` |

这样所有厂商都不需要特殊处理:OpenAI 两名相同显示一个;火山 `ark-code-latest` served 回显 `"auto"` 只显示 requested;自定义模型显示用户配的名字。

### 关键代码改动

文件:`libs/code/deepagents_code/textual_adapter.py`

1. 删除 `_looks_like_routing_alias()` 函数和 `_ROUTED_SEGMENTS` 常量(约 40 行)。
2. `_ROUTED_MODEL_SENTINELS` 重命名为 `_SERVED_MODEL_SENTINELS`,扩展为 `{"auto", "none", "null", ""}`。
3. `_render_model_label()` 从三分支(相同/兼容别名/路由别名)简化为纯数据驱动四分支(空/单边/sentinel/不同)。
4. `_format_model_call_info()` 的 docstring 去掉路由别名相关描述,`if requested_model or served:` 守卫简化为无条件调用。
5. 不再输出 `{req}(routed)` 标记——用户自己知道配的是路由别名,不需要 TUI 猜测。

### 后续 TODO

- 如果未来需要区分"路由别名"和"兼容别名",应通过 provider profile 配置,而非在 TUI 层硬编码命名模式。
- 探针脚本(`probe_huoshan*.py`, `probe_stream_meta.py`)仍散落在 `scripts/` 下,建议移到个人工具目录。

## 轮次 1 - 追加 tokens/ctx 显示的兜底修复

### 用户提问要点

- 元数据行只显示 `model=ark-code-latest  finish=stop  elapsed=31.1s`,缺少 `tokens in/out/total` 与 `ctx=used/limit~ (pct%)`。
- 用户已本地验证 `/model --model-params {"stream_usage": true}` 可让火山 gateway 回传 usage;要求把改动落到代码里。

### 根因

`_format_model_call_info`(`libs/code/deepagents_code/textual_adapter.py:215+`)的 tokens 与 ctx 两段完全依赖 stream chunk 上的 `usage_metadata`。对 OpenAI 兼容 gateway,LangChain 的 `ChatOpenAI` 只有在 `stream_usage=True` 时才会带 `stream_options={"include_usage": true}`,否则最后一个 chunk 没有 usage。仓库里没有任何地方默认开启该参数,所以第三方 gateway(火山 ark、DeepSeek、SiliconFlow 等)统一丢用量。

### 结论 / 方案(最小侵入)

1. **默认注入 `stream_usage=True`**
   `libs/code/deepagents_code/config.py::_get_provider_kwargs` 末尾追加:当 provider 是内置 `openai`,或其 `class_path` 以 `:ChatOpenAI` 结尾(涵盖 `save_custom_provider` 默认写入的 `langchain_openai:ChatOpenAI`)时,`result.setdefault("stream_usage", True)`。用户可通过 `params.stream_usage = false` 或 `--model-params` 覆盖。
2. **`save_custom_provider` 支持 `max_input_tokens`**
   `libs/code/deepagents_code/model_config.py::save_custom_provider` 新增 `max_input_tokens: int | None = None` 参数,当 `> 0` 时写入 provider config 的 `profile.max_input_tokens`,`create_model` 会自动把它 map 到 `settings.model_context_limit`,`ctx=used/limit~ (pct%)` 从此可以显示分母与百分比。
3. **`/add-provider` 命令**
   `libs/code/deepagents_code/app.py` 里的 `/add-provider` 增加第 7 个可选位置参数 `<max-input-tokens>`,并做整数与正数校验;usage 说明和示例更新。

### 关键代码位点

- `deepagents_code/config.py:3806-3826` — 新增 OpenAI 兼容 provider 的 `stream_usage=True` 默认逻辑。
- `deepagents_code/model_config.py:3660-3737` — `save_custom_provider` 增加 `max_input_tokens` 形参并写入 `[profile]` 子表。
- `deepagents_code/app.py:9485-9585` — `/add-provider` 命令新增 max-input-tokens 位置参数与校验,传给 `save_custom_provider`。

## 轮次 1 - 需求确认与实现

### 用户提问要点

- 希望每次调用大模型时,把返回的模型信息一同打印到屏幕上,方便观察。
- 通过 `ask_user` 明确:
  - 展示内容:`response_metadata / usage_metadata / finish_reason / 请求耗时`
  - 展示位置:每轮 AI 回复末尾追加一段(inline)

### 结论 / 方案

在 Textual TUI 的流处理器 `libs/code/deepagents_code/textual_adapter.py` 里,
按 namespace 维护"每次模型调用"的三项状态,并在该次模型调用的最后一个 chunk
(`chunk_position == "last"`) 到达时,把汇总信息作为一条 `AppMessage`
(TUI 里已有的"静音斜体"信息条)插入到聊天区,紧跟在 AI 回复之后。

关键点:
- **粒度是"每次模型调用",不是"每轮用户提问"**。一轮内如果发生多次工具调用,
  模型会被多次触发,元数据行会随之出现多次。这是响应元数据的自然粒度。
- 只对主 agent(`is_main_agent`) 打印,避免子 agent 输出污染主聊天区。

### 关键代码改动

文件:`libs/code/deepagents_code/textual_adapter.py`

1. 新增 `_format_model_call_info(usage, response_metadata, elapsed)`,输出形如:

   ```txt
   · model=doubao-seed-1-6  finish=stop  tokens in/out/total=100/50/150  cache_read=80  elapsed=3.4s
   ```

   - `model_name` 依次从 `response_metadata` 的 `model_name` / `model` / `model_id` 字段取。
   - `finish_reason` 兼容 `finish_reason` 与 `stop_reason`。
   - `tokens` 用 `usage_metadata` 的 `input_tokens` / `output_tokens` / `total_tokens`;
     缺 total 时用 in+out 补齐。
   - `cache_read` 从 `usage.input_token_details.cache_read`
     (或 `cache_read_input_tokens`) 取,只在存在时展示。
   - `elapsed` 使用 `formatting.format_duration` 格式化。

2. 在 stream 循环里追加三个 per-namespace 字典:

   ```python
   call_start_by_namespace: dict[tuple, float] = {}
   call_usage_by_namespace: dict[tuple, dict] = {}
   call_metadata_by_namespace: dict[tuple, dict] = {}
   ```

3. `messages` stream 分支里:
   - 首个 chunk 时记录 `time.monotonic()` 到 `call_start_by_namespace[ns_key]`。
   - 每个 chunk 尝试更新 `response_metadata` 与 `usage_metadata`(取最新非空值)。
   - `chunk_position == "last"` 时,针对主 agent,构造一行摘要 mount 一条 `AppMessage`;
     然后清空该 namespace 的三项记录,准备下一次模型调用。
