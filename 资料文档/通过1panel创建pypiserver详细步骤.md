# 1Panel 搭建私有 PyPI 仓库（pypiserver）完整操作文档
## 一、场景说明
### 环境信息
1. 服务器配置：2核2G
2. 管理面板：1Panel
3. 镜像：`pypiserver/pypiserver:latest`（本地已缓存，无需重新拉取）
4. 端口冲突：默认容器8080端口被占用，对外映射主机端口 `40001`
5. 功能需求：私有pip包仓库、账号密码鉴权、数据持久化、开机自启

### 前期踩坑记录
1. 首次拉取镜像报错 `403 Forbidden`：DaoCloud镜像源拦截匿名访问
2. 镜像名错误 `pypiserver:latest`：官方镜像完整名称为 `pypiserver/pypiserver:latest`，顶层library不存在
3. 再次拉取报错 `520`：1Panel自带镜像加速 `docker.1panel.live` 服务宕机，本次本地已有镜像，无需重新pull

## 二、1Panel 创建容器完整配置步骤
### 步骤1：进入创建容器页面
左侧菜单【容器】→ 顶部【创建容器】

### 步骤2：基础信息配置
| 配置项 | 填写内容 | 说明 |
| ---- | ---- | ---- |
| 名称 | pypi-server | 自定义容器名称 |
| 镜像 | pypiserver/pypiserver:latest | 下拉选择本地缓存镜像 |
| 手动输入 | 不勾选 | 已下拉选择，无需手动输入 |
| 强制拉取镜像 | 不勾选 | 本地已有镜像，避免触发520拉取报错 |

### 步骤3：端口映射（核心，解决8080占用）
- 模式：暴露端口
- 点击【添加】填写映射规则：
  - 服务器（主机端口）：`40001`（外部访问端口，自行按需修改）
  - 容器（内部固定端口）：`8080`（不可修改，pypiserver内置服务端口）
  - 协议：tcp
- 网络：保持默认 `bridge`，IPv4/IPv6输入框留空不填

### 步骤4：数据挂载（持久化，防止包丢失）
切换到挂载区域，选择【本机目录】，点击【添加】：
| 配置项 | 填写内容 |
| ---- | ---- |
| 本机目录 | `/opt/pypiserver/packages`（面板自动创建文件夹） |
| 权限 | 读写 |
| 容器目录 | `/data/packages` |
Command、Entrypoint 输入框全部留空，使用镜像默认启动命令

### 步骤5：启动与权限控制配置
1. 特权模式：不勾选
2. 容器退出后自动删除容器：不勾选
3. 控制台交互（伪终端、标准输入）：全部不勾选
4. **重启规则（必改）**：选择【一直重启】
   - 原默认「不重启」缺陷：服务器重启、容器崩溃后服务无法自动恢复
5. CPU权重：`1024`（保持默认，2核2G服务器无需调整优先级）
6. CPU限制：`0`（0=不限制核心，允许使用全部2核）
7. 内存限制：`0`（0=不限制内存，2G服务器完全够用）
8. 标签：留空不填写

### 步骤6：环境变量（仓库访问鉴权）
环境变量输入框填写一行，格式 `key=value`（无空格、无引号）
```
PYPISERVER_AUTH=admin:123456
```
- admin：自定义登录用户名，可修改
- 123456：自定义访问密码，建议替换为高强度密码
- 作用：访问仓库、上传下载whl包需要账号密码，禁止匿名访问

### 步骤7：确认创建
所有配置核对无误后，点击页面右下角【确认】，自动创建并启动容器。

## 三、容器启动后必做操作
### 1. 放行防火墙端口
服务器安全组、1Panel防火墙放行 `40001` TCP端口，否则外网无法访问私有仓库。

### 2. 访问仓库页面
浏览器访问地址：
`http://服务器公网IP:40001/simple/`
登录账号密码：配置的 `admin / 123456`

## 四、客户端使用教程
### 1. 上传本地whl安装包到私有仓库
1. 先安装上传工具twine
```bash
pip install twine
```
2. 上传命令
```bash
twine upload --repository-url http://服务器IP:40001/simple/ -u admin -p 123456 你的包文件名.whl
```

### 2. 从私有仓库安装Python包
#### 临时单次安装
```bash
pip install 包名 -i http://admin:123456@服务器IP:40001/simple/ --trusted-host 服务器IP
```
#### 全局配置永久使用（可选）
修改 `pip.conf` 配置文件，默认使用私有源。

## 五、常见问题与排查
1. 外网打不开页面：检查服务器安全组/防火墙是否放行40001端口
2. 忘记仓库密码：进入容器编辑页面，修改环境变量 `PYPISERVER_AUTH` 后重启容器
3. 容器启动失败：1Panel容器列表点击【日志】查看报错信息
4. 本地镜像丢失、重新拉取报错：修改Docker镜像加速器，替换为163/百度/中科大稳定源
5. 服务器重启后仓库消失：确认重启规则为「一直重启」

## 六、关键配置核对清单（下次新建快速自检）
- [ ] 镜像未勾选强制拉取
- [ ] 端口映射：40001:8080 tcp
- [ ] 挂载目录：/opt/pypiserver/packages → /data/packages 读写权限
- [ ] 重启规则：一直重启
- [ ] 环境变量配置账号密码 PYPISERVER_AUTH=xxx:xxx
- [ ] 防火墙放行主机端口40001
- [ ] CPU/内存限制保持0，权重1024默认不变


# 不删除容器、原地修改配置的方案（无需重建、原有包数据完全保留）
## 核心原理
1Panel支持**编辑运行中容器**，直接修改「Command启动命令」+清空旧环境变量，保存后重启容器即可，不用删容器、不用重新创建、原有包文件全部保留。

## 步骤1：进入容器编辑页面
1. 回到1Panel左侧【容器】菜单
2. 在容器列表找到 `pypi-server`，点右侧 **编辑** 按钮

## 步骤2：两处关键修改（重点）
### 修改1：清空环境变量（删掉旧鉴权）
滑到页面最下方「环境变量」输入框，把里面这一行**全部删除清空**：
```
PYPISERVER_AUTH=admin:123456
```
环境变量框保持空白，不要留任何内容。

### 修改2：填写Command启动参数（开启上传权限+文件鉴权）
往上滑动页面，找到 `Command` 输入框（挂载区域上方），粘贴下面完整参数：
```
-P /data/packages/.htpasswd -a download,update /data/packages
```
参数说明：
- `-P /data/packages/.htpasswd`：读取挂载目录下的密码文件鉴权
- `-a download,update`：允许上传(update)、下载(download)，两者都要密码
- `/data/packages`：你的包存储目录

## 步骤3：服务器SSH提前生成密码文件（必须先做！否则重启直接403）
先登录服务器终端执行，生成鉴权文件（容器挂载目录持久存储，重启不丢失）：
```bash
# 安装密码工具
apt update && apt install apache2-utils -y
# 创建密码文件，用户名admin，执行后输入2次密码123456
htpasswd -c /opt/pypiserver/packages/.htpasswd admin
```
执行完成后，`/opt/pypiserver/packages/` 下会生成 `.htpasswd`，容器内自动映射为 `/data/packages/.htpasswd`。

## 步骤4：保存配置并重启容器
1. 页面拉到最底部，点击【确认】保存配置
2. 回到容器列表，找到 `pypi-server`，点右侧 **重启** 按钮，等待容器重启完成

## 步骤5：重新执行上传命令
```bash
twine upload --repository-url http://8.152.204.58:40001/ -u admin -p 123456 deepagents_code-0.1.24-py3-none-any.whl
```
此时不会再报403禁止访问。

## 无需改动的原有配置（全部保留）
1. 端口映射 40001:8080 不变
2. 挂载目录 `/opt/pypiserver/packages` → `/data/packages` 不变
3. 重启规则「一直重启」不变
4. CPU/内存限制、网络、名称、镜像全部不用动

## 避坑提醒（关键）
1. **必须先生成.htpasswd文件，再重启容器**；如果先重启容器再生成文件，容器启动后鉴权文件不存在，访问直接报错。
2. 环境变量一定要清空，`PYPISERVER_AUTH` 和文件鉴权冲突，会导致鉴权失效。
3. twine上传地址只写根地址 `http://IP:40001/`，不要加simple/upload后缀。

## pip下载命令不变（不受本次修改影响）
```bash
pip install deepagents_code -i http://admin:123456@8.152.204.58:40001/simple/ --trusted-host 8.152.204.58
```
