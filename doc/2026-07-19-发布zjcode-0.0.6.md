# 发布 zjcode 0.0.6

## 版本内容

修复：首次启动 onboarding 流程中「Add Custom Provider」保存后，因为 dismiss payload 只回传裸模型名（如 `gpt-4o`），上层 `_switch_model → _retry_startup_with_model → create_model` 走 `detect_provider(bare_name)`，要么误判为 `openai`（用官方端点 + `OPENAI_API_KEY`），要么返回 `None`，导致用户填写的 `base_url` / `api_key` 完全被忽略，首次连接失败。

## 修复

`libs/code/deepagents_code/tui/widgets/model_selector.py` `action_add_custom_provider._on_provider_saved`：
- 修改前：`self._dismiss_with_result((model, provider_id))`（`model` 只是裸名）
- 修改后：`model_spec = f"{provider_id}:{model}"` → `self._dismiss_with_result((model_spec, provider_id))`

这样和 `/model` 命令 (`_select_with_auth_check` / `action_select`) 的返回格式一致，`create_model` 里 `ModelSpec.try_parse` 会解析出正确的 provider，走 `apply_stored_credentials` 拿到自定义 `base_url` / `api_key`。

## 测试

`libs/code/tests/unit_tests/tui/widgets/test_model_selector.py` 新增 `TestAddCustomProviderDismissal`（2 条 case），锁定回归。全套 162 条模型选择器单测通过。

## 发布流程

1. 预检：工作区干净、`learn` 分支、tag 未占用、PyPI 无 0.0.6。
2. `python libs/code/bump-version.py 0.0.6` → 三处版本号同步。
3. `uv lock` → `zjcode v0.0.5 -> v0.0.6`。
4. `uv build` 本地构建成功（wheel + sdist）。
5. 提交 4 个文件 → push `learn` → tag `zjcode-v0.0.6` → push tag → Actions 触发 Trusted Publisher。

## 用户侧操作

发布完成后（1–3 分钟）：
```bash
uv tool install zjcode --upgrade
zjcode --version   # expect 0.0.6
```
再走一遍 first-run onboarding + Add Custom Provider，应该能正常连接。
