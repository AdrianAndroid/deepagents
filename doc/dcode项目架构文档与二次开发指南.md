# Deep Agents Code (dcode) 项目架构文档 & 二次开发指南
---
## 一、项目架构文档
### 1. 项目定位
`deepagents-code`（简称`dcode`）是基于**Deep Agents SDK**构建的预构建终端编码代理产品，定位为终端内的AI编程助手，对标Claude Code、Cursor等工具，无需额外开发即可开箱使用，同时提供高度可扩展的二次开发能力。
核心特性：
- 交互式TUI终端界面，支持流式响应
- 跨会话持久化记忆，支持对话恢复
- 多LLM支持（默认内置OpenAI/Anthropic/Gemini，可选接入几乎所有主流模型）
- 内置Web搜索、文件操作、代码执行等工具
- 支持远程沙箱执行（LangSmith/AgentCore/Daytona/Modal等），保障本地环境安全
- 支持自定义技能/工具/MCP扩展
- 同时支持交互式模式和无头模式（可用于脚本、CI场景）
- 人在环审批机制，可控制工具调用权限

### 3. 核心架构设计
采用**客户端-服务端分离的进程架构**，两者通过流式协议通信：
```
┌──────────────────── 终端客户端 ─────────────────────┐
│  交互界面渲染、用户输入收集、人在环审批、结果展示     │
└──────────────────────────┬───────────────────────────┘
                           ▼  流式事件协议
┌──────────────────── Agent服务端 ─────────────────────┐
│  LangGraph工作流运行、模型调用、工具执行、记忆管理     │
└───────────────────────────────────────────────────────┘
```
**架构优势**：
- 界面响应与Agent运行解耦，避免大模型计算阻塞UI
- 服务端可独立测试、替换，支持不同前端接入
- 天然支持会话持久化和断点恢复
- 安全边界清晰，工具执行可完全隔离在服务端/沙箱内
### 4. 执行主流程
1. **启动阶段**：用户执行`dcode`命令 → CLI入口解析参数 → 初始化客户端TUI界面 → 启动独立的Agent服务进程 → 建立客户端与服务端的流式连接
2. **交互阶段**：用户输入指令 → 客户端发送请求到服务端 → 服务端加载会话历史 → 调用LLM生成下一步动作 → 执行工具调用（如需审批则暂停等待用户确认）→ 流式返回执行事件给客户端 → 客户端实时渲染输出
3. **结束阶段**：用户退出或会话结束 → 服务端持久化会话状态 → 关闭服务进程 → 客户端退出终端界面

## 二、二次开发完整学习步骤
### 1. 前置技术栈准备
| 技术领域 | 需掌握内容 | 学习优先级 |
|---------|-----------|-----------|
| 编程语言 | Python 3.11+ 语法、异步编程（async/await）、常用标准库 | ★★★★★ |
| AI框架 | LangChain基础、LangGraph工作流编排、LLM工具调用原理 | ★★★★★ |
| UI框架 | Textual终端UI框架、CSS基础、Rich终端渲染 | ★★★★☆ |
| 协议规范 | MCP（Model Context Protocol）协议、OpenAPI | ★★★☆☆ |
| 工程能力 | 虚拟环境管理（uv/venv）、Python包构建、调试工具使用 | ★★★★☆ |
### 2. 学习顺序（从入门到深入）
#### 阶段1：基础使用与环境搭建（1-2天）
1. 安装官方正式版`dcode`，熟悉所有功能和命令，了解产品能力边界
2. 拉取源码，按照`DEVELOPMENT.md`文档配置本地开发环境，启动开发版本
3. 运行官方示例，了解基础扩展方式（自定义工具、自定义技能）
#### 阶段2：源码结构学习（2-3天）
1. 从`main.py`入口开始梳理启动流程，理解客户端-服务端分离的启动逻辑
2. 阅读`ARCHITECTURE.md`、`COMMANDS.md`、`AGENTS.md`官方文档，理解设计理念
3. 分模块学习：先熟悉配置模块、会话模块，再学习客户端UI模块，最后学习服务端Agent模块
#### 阶段3：核心模块深入（3-5天）
1. 学习`server_graph.py`，理解LangGraph工作流的节点设计、状态流转逻辑
2. 学习`tools.py`和`mcp_tools.py`，掌握工具定义、注册、执行的全流程
3. 学习`skills/`目录下的内置技能实现，掌握自定义技能的开发方式
4. 学习`app.py`和`widgets/`目录，掌握Textual UI组件的开发和样式定制
#### 阶段4：扩展开发实践（5-7天）
1. 入门实践：修改终端主题、添加简单的自定义Slash命令、新增一个简单内置工具
2. 中级实践：接入一个新的LLM提供商、接入一个新的远程沙箱、修改Agent系统提示词
3. 高级实践：新增自定义子Agent工作流、修改核心工作流逻辑、对接内部业务系统
4. 性能优化：会话存储优化、大响应渲染优化、工具调用耗时优化
#### 阶段5：生产级定制（持续）
1. 企业级定制：对接内部SSO、添加企业内部知识库、配置企业级安全策略
2. 版本维护：跟进上游官方版本更新、合并上游特性、维护私有定制分支
3. 功能扩展：新增Web/IDE等其他前端、支持多用户协作、添加插件市场
### 3. 实践建议
1. **从小改动开始**：优先从技能、工具这类无侵入的扩展开始开发，再逐步深入核心逻辑
2. **充分利用现有扩展点**：官方已经提供了技能、工具、MCP、钩子等扩展点，尽量不要修改核心代码，降低后续版本合并成本
3. **测试先行**：所有新增功能都要添加对应单元测试，运行`make test`确保不破坏现有功能
4. **参考官方示例**：`examples/`目录下有大量官方示例，优先参考官方实现方式
5. **调试技巧**：客户端和服务端都有独立日志，调试时先定位问题属于客户端（UI/输入）还是服务端（Agent/工具/模型）
### 4. 注意事项
1. **安全边界**：默认`dcode`信任运行目录，自定义工具时一定要注意权限控制，避免恶意代码执行风险，不可信场景必须启用远程沙箱
2. **版本兼容**：`dcode`迭代速度快，依赖的Deep Agents SDK、LangGraph版本变化频繁，升级依赖时要充分测试兼容性
3. **配置分层**：配置支持用户/项目/会话多个层级，新增配置项时要遵循现有分层规则，不要硬编码配置
4. **协议兼容**：客户端和服务端的流式通信协议有版本要求，修改通信逻辑时要保证新旧版本兼容
5. **上游贡献**：通用性功能建议优先贡献给官方上游，减少私有分支维护成本
