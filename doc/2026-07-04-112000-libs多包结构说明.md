# libs 目录多包结构说明

- Time: 2026-07-04T11:20:00+08:00
- Project: deepagents

## 用户提问要点
用户看到 `libs/` 下有 `acp`、`cli`、`code`、`deepagents`、`evals`、`partners`、`talon` 等多个目录,询问它们是不是独立项目、彼此关系。

## 结论
`libs/` 是 monorepo,每个子目录都是**独立发布的 Python 包**(独立 `pyproject.toml`、独立版本号、独立发到 PyPI),但围绕核心 SDK `deepagents` 构成一个生态。

## 各包定位
| 目录 | PyPI 包名 | 作用 |
|---|---|---|
| `libs/deepagents` | `deepagents` | 核心 SDK,提供 `create_deep_agent()`、中间件、后端 |
| `libs/code` | `deepagents-code` | 终端编码 agent(`dcode`),Textual TUI、MCP、skills |
| `libs/cli` | `deepagents-cli` | 托管部署 CLI,部署到 LangSmith Managed Deep Agents |
| `libs/acp` | `deepagents-acp` | Agent Client Protocol 适配器(Zed 等编辑器) |
| `libs/evals` | `deepagents-evals` | 评测套件 + Harbor/CLBench 集成 |
| `libs/talon` | `deepagents-talon` | 本地长时运行时(实验性) |
| `libs/partners/*` | `langchain-daytona/-modal/-runloop/-vercel-sandbox/-quickjs` | 第三方沙箱/运行时集成 |

## 依赖关系
- 核心是 `libs/deepagents`,其它所有包都依赖它
- `libs/code` 依赖 SDK 和 quickjs 等 partner
- `libs/cli`、`acp`、`talon` 依赖 SDK
- `libs/evals` 同时依赖 SDK + code + quickjs
- 本地开发通过 `[tool.uv.sources]` 做 editable 源码链接,改核心 SDK 后 dcode 立刻生效

## 为什么这样拆
1. 独立版本发布,互不阻塞
2. 用户按需安装(只装 SDK / 只装 dcode)
3. Partner 依赖较重,拆成可选包
4. 一个 repo 统一管 CI、release-please、examples

## 二次开发聚焦
在 `libs/code` 二次开发,主要关心:
- `libs/deepagents/deepagents/` — 底层 API 和中间件
- `libs/code/deepagents_code/` — TUI、命令、provider、skills

其它 `acp`、`talon`、`partners`、`evals` 与 dcode 二次开发关系不大,可以先不管。
