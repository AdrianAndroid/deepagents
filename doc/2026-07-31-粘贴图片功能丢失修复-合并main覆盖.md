# 粘贴图片功能丢失修复 - 合并 main 分支导致 /paste-image 和 /copy-image 命令被覆盖

## 轮次 1 - 恢复丢失的粘贴图片功能

### 用户提问要点
用户发现粘贴图片的功能没有了，询问原因。

### 根因分析

`/paste-image` 和 `/copy-image` 命令是在以下 commit 中添加的自定义功能：
- `7cac7eab4` (2026-07-28): 首次添加 `/paste-image` 命令
- `2e36d3c06` (2026-07-30): 合并 main 后恢复品牌定制时，重新添加了 `/paste-image` 和 `/copy-image` 命令

**这些命令在后续合并 main 分支时被覆盖丢失**，具体丢失的是：
1. `command_registry.py` 中的 `/paste-image` 和 `/copy-image` 命令注册
2. `app.py` 中的 `/paste-image` 和 `/copy-image` 命令处理器
3. `media_utils.py` 中的 `save_pasted_media` 函数和 `PASTED_MEDIA_DIR` 常量

而 `get_clipboard_image()` 函数本身仍然存在于 `media_utils.py` 中，但没有任何地方调用它。

### 修复方案

恢复三处代码：

1. **`media_utils.py`**: 恢复 `PASTED_MEDIA_DIR` 常量和 `save_pasted_media()` 函数（在 `MAX_MEDIA_BYTES` 之后、`strip_media_placeholders` 之前）

2. **`command_registry.py`**: 在 `/copy` 命令后恢复 `/copy-image` 和 `/paste-image` 命令注册：
   - `/copy-image`: 复制最近粘贴的图片到剪贴板，`BypassTier.SIDE_EFFECT_FREE`
   - `/paste-image`: 从系统剪贴板粘贴图片，`BypassTier.QUEUED`，别名 `/paste-img`

3. **`app.py`**: 在 `/copy` 命令处理器之后、`/editor` 之前恢复两个命令处理器：
   - `/copy-image`: 从 `_image_tracker.images[-1]` 获取最近图片，调用 `copy_image_to_clipboard()`
   - `/paste-image`: 调用 `get_clipboard_image()` 读取剪贴板图片，通过 `_image_tracker.add_image()` 添加，调用 `save_pasted_media()` 保存本地归档

### 涉及文件

| 文件 | 改动 |
|---|---|
| `deepagents_code/media_utils.py` | 恢复 `PASTED_MEDIA_DIR` 常量和 `save_pasted_media()` 函数 |
| `deepagents_code/command_registry.py` | 恢复 `/paste-image` 和 `/copy-image` 命令注册 |
| `deepagents_code/app.py` | 恢复 `/paste-image` 和 `/copy-image` 命令处理器 |

### 测试结果
- `test_media_utils.py` + `test_chat_input.py`: 388 passed
- `/paste-image`、`/copy-image`、`/copy` 三个命令均在注册表中正确出现

### 经验教训
合并 main 分支后需要检查自定义功能是否被覆盖。`/paste-image` 和 `/copy-image` 是 zjcode 自定义命令，不在上游 main 中，每次合并都可能被丢失。建议使用 zjcode-brand-migration skill 进行品牌迁移检查时同时检查这些自定义命令是否存在。
