## 轮次 1 — dcode 启动时报升级失败,`install.sh` 却能装

### 用户提问要点
- 启动 `dcode` 出现:`Updating dcode from v0.0.6 to v0.1.36 (released 1d ago)...`,升级失败。
- 但 web 上的一键安装 `curl -fsSL http://8.152.204.58:40080/install.sh | bash` 是可以正常安装的。
- 问为什么。

### 关键证据
1. 当前已装版本(uv 视角):
   - `uv tool list` → `deepagents-code v0.0.6`
2. 私有 PyPI JSON 元数据(`_version.py` 里的默认 `PYPI_URL`):
   - `http://8.152.204.58:40080/pypi/deepagents-code/json`
   - `info.version = "0.0.6"`,`releases` 只到 `0.0.6`
3. 但本地缓存写了个更高的版本 `~/.deepagents/.state/latest_version.json`:
   ```json
   {"version":"0.1.36","version_prerelease":"0.1.36",
    "release_requires_prereleases":{"0.0.4":false,"0.1.36":true},
    "checked_at":1783732305.669323}
   ```
   `checked_at` → `2026-07-11T01:11:45Z`,`CACHE_TTL = 86_400`(24h),启动时短路命中缓存,不再重拉。
4. 实际触发的升级命令(见 `~/.deepagents/.state/update_logs/*-update.log`):
   ```
   uv tool install -U 'deepagents-code[anthropic,google-genai,media,openai]==0.1.36' --prerelease allow
   ```
   **注意:没有 `--index-url` 指向私有 PyPI**。
5. `~/.pip/pip.conf` 是清华镜像(镜像同步了公网 PyPI 上 langchain-ai 上游的 `deepagents-code`,主线 `0.1.x`);uv tool 默认索引也会走公网/镜像。

### 根因结论
`install.sh` 的两道安全防线,dcode 内置自动更新完全没有采纳:

| 防线 | `install.sh` | 内置自动更新 (`update_check.py -> upgrade_command()`) |
| --- | --- | --- |
| 显式 `--index-url` 指向私有 index | ✅ | ❌ |
| 只 pin 私有独有的 `0.0.x` 版本 + 安装后校验 `NEW_VER_NUM` 必须 `0.0.*` | ✅ | ❌ |

后果:
- pin 的 `==0.1.36` 在私有 index **不存在**,或者被解析到公网 langchain-ai 上游的同名不相关包(其依赖/extras 完全对不上),必然报错。
- `install.sh` 里那一大段注释就是在解释这个"同名包冲突"问题:私有 index 的 `0.0.x` 与公网 `0.1.x` 是**两个不同项目共用了同一个包名**,依靠"独有版本号 pin"来做隔离。

### 缓存值 `0.1.36` 是怎么来的
过去某次 `PYPI_URL` 返回过 `0.1.36`(可能环境变量 `DEEPAGENTS_CODE_PYPI_URL` 一度指过公网,或私有 JSON 一度错发过公网 metadata)。当时写入缓存后,后续 24h 内启动都会信这个缓存,而不去重新拉私有 JSON。现在私有 JSON 已经恢复到 `0.0.6`,但缓存 TTL 没过期,所以还在错。

### 修复方案(给用户)
- A. **清缓存**(推荐,一次性解决当次问题):
  ```bash
  rm ~/.deepagents/.state/latest_version.json ~/.deepagents/.state/update_state.json
  ```
- B. **彻底关闭自动更新**,留在私有 `0.0.x`。在 `~/.deepagents/config.toml` 追加:
  ```toml
  [update]
  auto_update = false
  ```
- C. **想升级**:重跑 `install.sh`,它才会走 `--index-url` + `unsafe-best-match` + 独有版本 pin 的安全路径。

推荐 A + B 组合。

### 沉淀知识:如果要修「私有分叉的自动更新」根因(TODO)
自动更新命令生成在 `libs/code/deepagents_code/update_check.py`,构造点包括 `upgrade_command()` / `_dependency_refresh_command()` / `_upgrade_from_receipt()` 等(搜 `uv tool install -U` 就能找齐)。要真正安全,得让这些命令:

1. 从 `PYPI_URL` 推导出私有 Simple index(把 `/pypi/<pkg>/json` 换成 `/simple/`),并作为 `--index-url` 注入;
2. 保留 `--extra-index-url https://pypi.org/simple/`(传递依赖仍需公网);
3. 加 `--index-strategy unsafe-best-match`;
4. 装完后校验版本必须落在私有段(如 `0.0.x`),否则 rollback / 报错。

即"把 `install.sh` 的策略搬进 update_check.py"。目前是 web 一键装能用、启动内自动升级不能用的原因就在这。

### 相关文件
- `libs/code/deepagents_code/update_check.py` — 自动更新逻辑、缓存、命令构造
- `libs/code/deepagents_code/_version.py` — `PYPI_URL` / `SDK_PYPI_URL` 默认值(私有 JSON API)
- `libs/code/deepagents_code/_env_vars.py` — `DEEPAGENTS_CODE_PYPI_URL` / `DEEPAGENTS_CODE_SDK_PYPI_URL`
- `install.sh`(私有站点上,来源见项目内 `scripts/install.sh`)— 安全安装参考实现

## 轮次 3 — 再次遇到 `Updating dcode from v0.0.6 to v0.1.36`,定位并修复根因

### 用户提问要点
- 启动 `dcode` 又出现 `Updating dcode from v0.0.6 to v0.1.36 (released 1d ago)...`。
- 重申 web 一键安装 `curl -fsSL http://8.152.204.58:40080/install.sh | bash` 能正常装。

### 诊断证据链
1. `install.sh` 本身正常:实跑后正确安装私有 `v0.0.6`(`--index-url` 私有 + `unsafe-best-match` + 独有版本 pin)。
2. 已装 `v0.0.6` 的 `_version.py` 默认 `PYPI_URL = http://8.152.204.58:40080/pypi/deepagents-code/json`(私有镜像),用装好的解释器 import 验证过。
3. 私有镜像 JSON 正确返回 `info.version: 0.0.6`,releases 仅 `0.0.1~0.0.6`。
4. **元凶 = 被污染的缓存** `~/.deepagents/.state/latest_version.json`:
   - 内容 `{"version": "0.1.36", ... "release_requires_prereleases": {"0.0.4": false, "0.1.36": true}}`
   - `checked_at` = 今天 09:11,仍在 24h TTL(`CACHE_TTL=86400`)内 → 启动被信任。
5. `~/.deepagents/.state/update_logs/20260711-011125-update.log` 显示 09:11 那次用旧构建 `0.0.3`,跑的是**未固定版本**的 `uv tool install -U 'deepagents-code[...]'`,把公网无关包 `0.1.32→0.1.36` 装了进来,并写下污染缓存。

### 根因结论
- 旧私有构建(`0.0.3`,默认查公网 PyPI)的内置自动更新器,把公网上 langchain-ai 的同名无关包 `deepagents-code 0.1.x` 当成新版,写入了缓存 `latest_version.json`。
- 之后重装回私有 `0.0.6`(已默认私有镜像),但**污染缓存仍在 TTL 内**,每次启动读缓存 → 又想升级到错误的公网 `0.1.36`。
- 即:`install.sh` 走的是安全 pin 路径没问题;问题在于**残留的过期缓存**驱动了错误升级。

### 修复操作(已执行并验证)
```bash
rm -f ~/.deepagents/.state/latest_version.json
# 清理 update_state.json 里过期通知标记(保留 auto_update_default_acknowledged)
```
验证:用已装解释器调用 `is_update_available(bypass_cache=True)` → `update_available: False, latest: 0.0.6`;缓存被重写为正确的 `0.0.6`。

### 关键操作 / 文件改动
- 删除 `~/.deepagents/.state/latest_version.json`(污染缓存)。
- 清理 `~/.deepagents/.state/update_state.json`,仅留 `auto_update_default_acknowledged`。
- 未改任何仓库源码。
