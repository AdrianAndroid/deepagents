### 轮次 - Windows setup-dev-env.ps1 测试与修复

**用户提问要点：** 测试 `libs/code/setup-dev-env.ps1`，找出运行问题并修改脚本。

**测试与修复过程：**
1. 直接运行脚本时，PowerShell 报 `}` 解析错误。根因：`.ps1` 文件以 UTF-8 无 BOM 保存，Windows PowerShell 5.1 默认按系统 ANSI 编码（GBK）读取，导致中文注释的字节被误解码、若干换行被吞掉（93→83 行），大括号匹配错乱。
   - 修复：为 `libs/code/setup-dev-env.ps1` 添加 UTF-8 BOM。
2. 再次运行时，脚本检测到 conda，但报错“无法定位 conda 初始化脚本 (conda.ps1)”。根因：原脚本照搬 Linux 路径 `etc/profile.d/conda.ps1`，而该 Windows Miniconda 安装的 PowerShell hook 实际位于 `shell/condabin/conda-hook.ps1`。
   - 修复：
     - 优先通过 `$env:CONDA_EXE`、`Get-Command conda` 或常见安装路径定位 `conda.exe`。
     - 使用 `shell/condabin/conda-hook.ps1` 作为 PowerShell hook，并保留 `etc/profile.d/conda.ps1` 作为兼容回退。
     - hook 加载后再次校验 `Get-Command conda` 是否成功。

**关键操作或文件改动：**
- 新增/修改文件：`libs/code/setup-dev-env.ps1`（未跟踪文件 `?? libs/code/setup-dev-env.ps1`）
- 内容变更：
  - 开头增加 UTF-8 BOM。
  - conda 探测逻辑增强，支持 `$env:CONDA_EXE`、已加载的 `conda` 函数、常见安装目录候选。
  - PowerShell hook 路径改为 `shell/condabin/conda-hook.ps1`。
  - 使用 `Join-Path` 拼接 Windows 路径。

**测试结果：**
- 使用临时环境变量 `$env:ENV_NAME="dcode-dev-test"`、`$env:PYTHON_VER="3.12"` 完整跑通：
  - 成功创建 conda 环境 `dcode-dev-test`（Python 3.12.13）。
