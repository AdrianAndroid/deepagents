# 2026-07-19 — 为 `/model` 添加"发现可用模型"能力

## 需求

用户在自定义 OpenAI-compatible provider 时，希望能一键从 provider 的 `/models`
接口拉取模型列表并挑选多个模型加入配置，而不是每次只能手写一个 `default_model`。

## 结论

在 `Add Custom Provider` modal 里新增一个 **Discover** 按钮：

1. 校验 `Base URL` / `API Key`（编辑模式下 Key 为空时自动读取 `auth_store` 中已存的凭据）
2. 调用 `GET {base_url}/models` 拉取列表
3. 弹出多选框（`SelectionList`）供用户勾选，支持 `Ctrl+A` 全选、`Ctrl+N` 全清
4. 用户确认后：
   - 把勾选集合写入 `[models.providers.<id>].models`
   - 如果原 `default_model` 不在勾选集合里，自动改成勾选集合的第一项
   - 若用户没打开 Discover 直接保存，行为完全兼容旧版（`models=[default_model]`）

同时修复了原本"编辑模式下按 Confirm 会把 `models` 列表覆盖回单元素"的隐患：
现在编辑模式启动时会把 `models` 已有的所有条目预加载到 `_discovered_models`，
Confirm 时一并写回。

## 关键改动

### `libs/code/deepagents_code/model_config.py`

- 新增 `class ModelDiscoveryError(Exception)`：用户可见的发现失败异常
- 新增 `def fetch_provider_models(base_url, api_key, *, timeout=10.0, include_retiring=True) -> list[str]`：
  - 走 `httpx.get`
  - 兼容 OpenAI shape (`{"object":"list","data":[{"id":...}]}`) 和裸列表两种响应
  - 过滤 Volcengine Ark 的 `status="Shutdown"`（可选连 `Retiring` 一起过滤）
  - 401/403/404/其他 4xx-5xx 都转成 `ModelDiscoveryError` 带明确文案
  - 返回去重且排序的 `list[str]`

## 现网验证（手工调 `/models`）

针对 `~/.deepagents/config.toml` 中的 `huoshan` provider：

```
base_url = https://ark.cn-beijing.volces.com/api/coding/v3
```

`fetch_provider_models` 直接调用返回 **60 个非 Shutdown 模型**，包括
`glm-4-5-air-20250728`、`qwen3-32b-20250429`、`doubao-smart-router-250928` 等。
`ark-code-latest` 属于路由 alias，不会出现在返回列表里 —— 这是 Volcengine
Ark 的既有行为，符合预期。

## 使用方式

1. `/model` → `+` (Add custom provider)
2. 填 `provider_id` / `display_name` / `base_url` / `api_key`
3. 点 **Discover** → 弹出多选框 → 勾选目标模型 → **Save selection**
4. 回到 provider modal 点 **Confirm**，即写入 config.toml

编辑既有 provider 时同理，Discover 会自动带上已有的选择。
