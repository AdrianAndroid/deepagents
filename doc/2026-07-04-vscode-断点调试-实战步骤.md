# 2026-07-04 VSCode 断点调试 deepagents-code 实战指南

## 项目背景

- 包名：`deepagents-code`（命令 `dcode` / `deepagents-code`）
- 入口：`deepagents_code:cli_main`（在 `libs/code/deepagents_code/__init__.py`）
- 类型：Textual 终端 UI（TUI）
- 虚拟环境：`libs/code/.venv`（由 `run-setup-dev-env.sh` / `dcode-dev.sh` 创建）
- 已配置 `.vscode/settings.json` 指向该解释器

## 一、准备工作（一次性）

### 1. 确认解释器

`.vscode/settings.json` 已有：
```json
"python.defaultInterpreterPath": "./libs/code/.venv/bin/python"
```

若不存在，运行：
```bash
cd /Users/zhaojian/code/deepagents/libs/code
./run-setup-dev-env.sh   # 或 ./dcode-dev.sh
```

VSCode 中 `Cmd+Shift+P` → `Python: Select Interpreter` → 选 `./libs/code/.venv/bin/python`。

### 2. 装扩展

必装：**Python**（Microsoft，自带 debugpy）。

### 3. `launch.json`

已生成在 `/Users/zhaojian/code/deepagents/.vscode/launch.json`，包含 4 个场景：
- **dcode: TUI (module)** — 调试 TUI 主入口
- **Python: 当前文件** — 调试任意脚本
- **Pytest: 当前文件** — 调试测试
- **Attach: localhost:5678** — 附加到运行中的进程

## 二、实战步骤（三种典型场景）

### 场景 A：调试 dcode TUI 启动/交互流程 ⭐ 最常用

1. 打开 `libs/code/deepagents_code/main.py` 或 `app.py`
2. 在感兴趣的函数（如 `cli_main`、`App.on_mount`）行号左侧点击打断点（红点）
3. 左侧栏 → 调试图标（`Cmd+Shift+D`）
4. 顶部下拉框选 **"dcode: TUI (module)"** → 点绿色三角（或 F5）
5. VSCode 会在集成终端里以模块方式启动 `python -m deepagents_code`
6. TUI 渲染后与其交互，触发到断点会自动暂停，回到 VSCode 编辑器

> ⚠️ TUI 会接管终端，触发断点时终端可能残留 UI 字符；这是正常的，看编辑器的调试视图即可。

### 场景 B：调试某个单元测试（推荐用于业务逻辑）

1. 打开要调试的测试文件（如 `libs/code/tests/unit_tests/test_xxx.py`）
2. 在测试函数或被测函数里打断点
3. 选 **"Pytest: 当前文件"** → F5
4. Debug Console 里可以输入表达式实时查看

也可以在测试函数上方点 VSCode Python 扩展自动生成的 **"Debug Test"** codelens。

### 场景 C：Attach 到已运行的 dcode

用于线上/守护进程排查，或不方便直接 F5 启动时。

1. 在代码入口处（如 `main.py` 顶部）临时加：
   ```python
   import debugpy
   debugpy.listen(("localhost", 5678))
   print("Waiting for debugger...")
   debugpy.wait_for_client()
   ```
2. 正常运行 `dcode`（在集成终端 or 外部终端）
3. VSCode 选 **"Attach: localhost:5678"** → F5
4. 附加成功后即可命中后续断点

## 四、进阶技巧

### 1. 条件断点
右键断点红点 → **Edit Breakpoint** → 输入表达式，如 `user_id == 42`。仅在条件满足时暂停。

### 2. Logpoint（日志断点，不暂停）
右键行号 → **Add Logpoint** → 输入 `state = {state}`。表达式用 `{}` 包裹。适合排查无法轻易停下的循环 / 异步流程。

### 3. 异常断点
BREAKPOINTS 面板勾选：
- `Raised Exceptions` — 任何抛出（噪音大）
- `Uncaught Exceptions` — 只捕获未处理异常（推荐）

### 4. `justMyCode: false`
本项目 launch.json 已设置。允许步入 `deepagents`、`langchain`、`textual` 等依赖库源码，排查框架问题时必开。

### 5. Debug Console
暂停时可以：
- 输入任意 Python 表达式：`self.state.messages[-1]`
- 修改变量：`x = 100`
- 调用函数验证：`compute_hash(data)`

### 6. 调试 subagent / 异步代码
- 在 `async def` 里同样能打断点
- Textual 用 asyncio，Step Over 可能跳过 await 内部逻辑 → 用 Step Into 或直接在内部函数里打点

## 五、常见坑

| 症状 | 原因 / 解决 |
|---|---|
| 断点变灰空心圈 | 解释器不对 → 重选 interpreter，确认是 `libs/code/.venv/bin/python` |
| `ModuleNotFoundError: deepagents_code` | `cwd` 不对，或包未 editable 安装 → 跑 `./dcode-dev.sh` |
| TUI 花屏，看不到 stdout | 正常现象，看 VSCode 调试视图；或用 Attach 模式 |
| 断点命中后无法输入 | 焦点在 TUI 上 → 点回 VSCode 编辑器 |
| 无法进入依赖库 | `justMyCode` 设为 `false`（本 launch.json 已默认关闭）|
