## 0. 30 秒读懂全貌

Deep Agents 是一套"长时运行的编码代理"框架，分层堆叠在两个已有产品之上：

```
┌─────────────────────────────────────────────────────────────────┐
│  用户交互层        deepagents-code   deepagents-acp   deepagents-talon
│                   (Textual TUI)     (IDE 协议)        (长时宿主)    │
├─────────────────────────────────────────────────────────────────┤
│  评估与发布        deepagents-evals   partners/{daytona,modal,...} │
├─────────────────────────────────────────────────────────────────┤
│  代理框架          deepagents   =  LangChain create_agent()  +  opinionated harness
├─────────────────────────────────────────────────────────────────┤
│  运行时            LangGraph   =   状态 / checkpoint / streaming / interrupt
└─────────────────────────────────────────────────────────────────┘
```

**核心论断**（[ARCHITECTURE.md](../libs/ARCHITECTURE.md) 已阐明）：Deep Agents 没有自己的 runtime，**它是对 LangChain `create_agent()` 的 opinionated 包装**。所以"Deep Agents 添加了什么"这个问题的答案是：**默认中间件栈 + 后端抽象 + 子代理 + 技能 + 记忆 + profile**。把 LangChain 的 `create_agent` 看成没有肉的骨架，Deep Agents 决定哪块肉该放哪。

## 3. 三层架构（核心概念）

来自 [`libs/ARCHITECTURE.md`](../libs/ARCHITECTURE.md)：

| 层 | 来源 | 职责 |
|---|---|---|
| **LangGraph** | 第三方库 | 运行时：state、checkpoint、streaming、interrupts |
| **LangChain `create_agent()`** | 第三方库 | 代理抽象：model + tools + middleware → agent 循环 |
| **Deep Agents** | 本仓库 | opinionated 包装：**默认中间件栈** + **backend 抽象** + **subagent** + **skills** + **memory** + **profile** |

当你遇到行为问题，先问"它属于哪一层"：

- 模型被叫了几次、流式输出、checkpoint 怎么存 → LangGraph 层
- `wrap_model_call` 钩子、tool 列表被改、prompt 注入 → LangChain `create_agent` + Deep Agents middleware 层
- 文件存在哪、execute 在哪跑、文件大小限制 → Deep Agents backend 层

**Deep Agents 自己的代码集中在三处**：

1. `libs/deepagents/deepagents/middleware/` — 行为注入
2. `libs/deepagents/deepagents/backends/` — 文件/执行落地
3. `libs/deepagents/deepagents/profiles/` — 按模型/Provider 调节默认

### 4.3 后端系统（`deepagents/backends/`）

**协议**：

- `BackendProtocol`（`backends/protocol.py:378`）— 必实现：ls/read/write/edit/glob/grep/download/upload，每对都有 sync + async
- `SandboxBackendProtocol(BackendProtocol)`（`backends/protocol.py:793`）— 增加 `execute()`

**内置实现**：

| Backend | 位置 | 存储 | execute? |
|---|---|---|---|
| `StateBackend` | `backends/state.py:37` | LangGraph state `files` channel | 否 |
| `FilesystemBackend` | `backends/filesystem.py:91` | 真实磁盘 | 否 |
| `LocalShellBackend` | `backends/local_shell.py:26` | 真实磁盘 + 本机 shell | **是** |
| `StoreBackend` | `backends/store.py:89` | LangGraph `BaseStore`（跨 thread） | 否 |
| `CompositeBackend` | `backends/composite.py:178` | 路由 | 否（除非 default 是 sandbox） |
| `BaseSandbox` | `backends/sandbox.py:952` | 抽象 | **是** |
| `LangSmithSandbox` | `backends/langsmith.py:56` | 远端 | **是** |

**学习路径**：先读 `backends/protocol.py` → `backends/state.py` → `backends/filesystem.py` → `backends/composite.py`。

### 4.4 状态管理（Deep Agents 的隐藏创新）

- **`DeepAgentState`**（`graph.py:70-73`）：把 `messages` 字段升级为 `DeltaChannel(_messages_delta_reducer, snapshot_frequency=50)`，**长 thread 的 checkpoint 从 O(N²) 降到 O(N)**
- **`FilesystemState.files`**（`filesystem.py:996`）用同样模式
- **`PrivateStateAttr`**（`middleware/_state.py:13`）：标了此属性的字段在 subagent 出入站时被剥离，**防止内部细节泄漏到子代理**

### 4.5 子代理三态

| Spec | 字段 | 编译方式 | 接入 |
|---|---|---|---|
| `SubAgent`（declarative） | name/description/system_prompt + tools/model/middleware/... | `langchain.agents.create_agent` 编译为 `Runnable` | `SubAgentMiddleware` 注册 `task` 工具 |
| `CompiledSubAgent` | name/description + `runnable: Runnable` | **直接用** caller 给的 `runnable` | 同上，**不继承** `state_schema`/`interrupt_on` |
| `AsyncSubAgent` | name/description + `graph_id`（必填） | 远程 LangGraph SDK 调用 | `AsyncSubAgentMiddleware` 注册 5 个异步任务管理工具 |

详见 `middleware/subagents.py` 与 `middleware/async_subagents.py`。

### 4.6 Profiles 体系

- **`HarnessProfile`**（`profiles/harness/harness_profiles.py:483`）：运行时生效，控制 prompt 装配、工具排除、extra_middleware、GP subagent
- **`ProviderProfile`**（`profiles/provider/provider_profiles.py:38`）：模型构造时生效（kwargs、headers）
- 内置 profile 通过 `_builtin_profiles.py` + `_anthropic_*.py` 等注册，按 `provider:model` 匹配

## 9. 一些非显然的设计选择

理解这些会少走很多弯路：

1. **Deep Agents 没有自己的 runtime** — 所有执行走 LangGraph。所以"卡住/重启/中断"问题去查 LangGraph 文档，不是本仓库
2. **CLI 通过 HTTP+SSE 连 server，不走 IPC** — 进程隔离容易部署；server 端可以独立扩展
3. **`app.py` 是 25481 行的巨型文件** — 历史原因；按 `AGENTS.md` 不强制拆分。tui 子组件已抽到 `tui/widgets/`，核心 App 留在原地
4. **命令注册 `COMMANDS` 是单一来源** — bypass 派别、autocomplete 列表、drift 测试都从这推导
5. **`FilesystemState.files` 用 `DeltaChannel`** — 与 `messages` 字段同模式，长 thread 不再 quadratic checkpoint
6. **`HarnessProfile` 与 `ProviderProfile` 分工** — Provider 在模型构造时（`init_chat_model` 阶段），Harness 在代理运行时
7. **subagent 不会泄漏内部 state** — `PrivateStateAttr` 标记的字段在子代理出入站时被剥离
8. **`talon` 依赖 `code` 而非 `deepagents`** — 因为它要接管 CLI 进程做长时编排
9. **没有 `tools/`、`executor.py`、`command_run.py`** — 这些是 `libs/cli` 旧时代的概念，已迁出
