## 轮次 2 - 1Panel 终端里 dcode 运行时鼠标事件泄漏

**用户提问**（附截图）：在 1Panel 终端里运行 deepagents 时，任何操作（比如鼠标移动/滚动）都会有类似 `[<35;36;33M7MM34M[<35;86;32M<0;15;...` 的转义字符注入到输入框。

### 问题根因

- Textual 启动时向终端发送 `\x1b[?1000h`（VT200 mouse）与 `\x1b[?1006h`（SGR 扩展模式），开启鼠标追踪
- 鼠标一动，1Panel 使用的 Web 终端（xterm.js/ttyd 类）会把鼠标事件封装成 SGR 上报序列 `\x1b[<Cb;X;YM` 回传
- 但 1Panel 的这类 Web 终端在转发时会把 **ESC 前缀吞掉或转码**，导致 Textual 收到的是残缺的 `[<35;36;33M...`，无法作为鼠标序列识别，就当成普通字符注入了 `ChatInput`

### 修复方案（源头关闭鼠标追踪）

新增两条对等入口，二者任一开启即让 Textual 不再发 `1000h/1006h`：

1. **CLI 开关** — `--no-mouse`
   - 注册在 `deepagents_code/main.py` 的 `parser.add_argument(...)`
   - 帮助文本同步补充到 `deepagents_code/ui.py`（`show_help`）
2. **环境变量** — `DEEPAGENTS_CODE_NO_MOUSE`
   - 注册在 `deepagents_code/_env_vars.py`（常量 `NO_MOUSE`）
   - 值解析走 `is_env_truthy`（`1/true/yes/on`）

管线：
- `main.py::_resolve_no_mouse(args)` — 融合 CLI + 环境变量，返回 bool
- `main.py::run_textual_cli_async(..., mouse: bool = True)` — 新增关键字参数
- `app.py::run_textual_app(..., mouse: bool = True)` — 新增关键字参数
- `app.py` 最终 `await app.run_async(mouse=mouse)` — 传给 Textual

### 涉及文件

| 文件 | 改动 |
| --- | --- |
| `libs/code/deepagents_code/_env_vars.py` | 新增 `NO_MOUSE` 常量与说明 |
| `libs/code/deepagents_code/main.py` | 加 `--no-mouse` argparse 参数、`_resolve_no_mouse` 辅助函数、`run_textual_cli_async` `mouse` 参数、在调用 `run_textual_app` 时传入 |
| `libs/code/deepagents_code/app.py` | `run_textual_app` 加 `mouse` 参数、`app.run_async(mouse=mouse)` |
| `libs/code/deepagents_code/ui.py` | `show_help` 增加 `--no-mouse` 帮助行 |

### 验证

- `uv run dcode --help` 中出现 `--no-mouse` 行
- 自测：无参/`--no-mouse`/`DEEPAGENTS_CODE_NO_MOUSE=1|0` 四种组合，`_resolve_no_mouse` 返回值正确
- `ruff check` 未引入新错误（原本 8 个错误在 `/add-provider` 命令块，与本改动无关）

### 使用方式

用户在 1Panel 网页终端里跑 dcode 时，任选其一：

```bash
dcode --no-mouse
# 或
DEEPAGENTS_CODE_NO_MOUSE=1 dcode
```
