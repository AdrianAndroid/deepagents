# 2026-07-19 新增 Provider 后立即生效方案

## 用户提问

> 新增添的 Provider，点击 confirm 后，能不能直接显示在第一张的目录里，如果不行可以直接使用新的 provider 然后立即生效，然后关闭所有弹窗。哪个方案侵入性小，选择哪个方案

用户提供了两张截图：
1. `/model` 选择器界面，显示模型分组列表（Recent / huoshan / OpenAI / ...）
2. Add Custom Provider 表单弹窗，包含 Provider ID / Display Name / Base URL / API Key / Default Model

## 方案对比

### 方案 A：新 Provider 直接显示在第一张目录里
- 需要修改 `_update_display` 或 `_reload_model_list` 排序逻辑
- 要记录"哪个是新添加的 provider"，然后在分组排序时把它置顶
- 修改点：`_provider_availability_rank` 或 `_reload_model_list` 内加一个 pinned 提示
- 侵入范围：约 20~30 行，涉及分组/排序，且需要额外状态字段（"新增标记"）
- 用户还得多按一次 Enter 才能真正切过去

### 方案 B（选中）：确认后直接使用新 provider 并关闭所有弹窗
- 只需改 `_on_provider_saved` 回调 + `CustomProviderModalScreen.action_submit` 的 dismiss 返回值
- 有 `default_model` 就用它；没有则用占位 `custom_model`（用户可稍后 `/model` 再选）
- 侵入范围：约 10 行，无需触碰分组/排序逻辑
- 一次操作即可切换，UX 更好

**结论：方案 B 侵入性明显更小，且用户体验更好，直接采用。**

## 关键改动

文件：`libs/code/deepagents_code/tui/widgets/model_selector.py`

1. `CustomProviderModalScreen` 泛型从 `ModalScreen[bool]` 改为 `ModalScreen[bool | tuple[bool, str, str | None]]`
2. `action_submit` 成功时 `dismiss((True, provider_id, default_model))`，而非 `dismiss(True)`
3. `ModelSelectorScreen.action_add_custom_provider` 里的 `_on_provider_saved`：
   - 兼容旧 bool 返回和新 tuple 返回
   - 保存成功且拿到 `provider_id` 时，用 `default_model or "custom_model"` 组装 `(model, provider_id)`
   - 调用 `self._dismiss_with_result(...)` 一步关掉整个模型选择器 + 添加弹窗，并把选中结果回传给上层，触发模型切换
   - 保留旧的 reload 分支作为 fallback（防御式）
