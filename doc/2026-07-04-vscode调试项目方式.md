## 轮次 1 - 项目如何用 VSCode 调试 / 有无调试插件

### 用户提问要点

- 使用 VSCode 开发本项目
- 想知道如何进行 debug 调试
- 想确认项目里是否有调试相关的插件配置

### 结论 / 方案

**VSCode 配置现状**

- `.vscode/extensions.json` 推荐的插件（都不是专用 debug 插件，但 Python 插件自带 debugpy 调试器）：
  - `ms-python.python` — Python 调试器（含 debugpy），F5 断点调试的核心
  - `charliermarsh.ruff` — Lint / Format
  - `astral-sh.ty` — 类型检查（Astral 出品）
  - `davidanson.vscode-markdownlint`
  - `github.vscode-pull-request-github`
  - `github.vscode-github-actions`
  - `redhat.vscode-yaml`
  - `editorconfig.editorconfig`
- `.vscode/settings.json` 已指定 Python 解释器：`./libs/code/.venv/bin/python`
- **没有** `.vscode/launch.json`，也没有 `tasks.json`——即 VSCode 一键 F5 调试**没有预置配置**，需要自建。

**项目官方推荐的调试方式**（来自 `libs/code/DEVELOPMENT.md`）

Deep Agents Code 是**双进程**架构：Textual TUI + `langgraph dev` 子进程。官方推荐用日志调试，而不是 VSCode 断点：

```bash
cd libs/code
export DEEPAGENTS_CODE_DEBUG=1
uv run deepagents-code
```

| 症状 | 看哪个日志 | 位置 |
|---|---|---|
| 启动崩溃（TUI 只显示一行 banner） | 服务端子进程日志（含真实 traceback） | `$TMPDIR/deepagents_server_log_*.txt` |
| 启动后行为异常（UI、模型调用、slash command） | 客户端 app 日志（`DEBUG` 级别） | `/tmp/deepagents_debug.log` |

- `DEEPAGENTS_CODE_DEBUG=1` 是总开关，保留服务端日志文件并挂 client 的 DEBUG handler
- `DEEPAGENTS_CODE_DEBUG_FILE=<path>` 可覆盖 client 日志路径（仅在开关打开时生效）
- 实时看日志：`tail -f /tmp/deepagents_debug.log`
- 关键搜索词：`Failed to initialize server graph`——它下面就是真正的异常栈

**Textual 开发时的 CSS/日志热重载**（DEVELOPMENT.md 末尾）

- 需要写个 `/tmp/dev_deepagents.py` wrapper
- 终端 1：`uv run --group test textual console`
- 终端 2：`uv run --group test textual run --dev /tmp/dev_deepagents.py`
- 编辑 `.tcss` 即时生效，`self.log()` 打到 console

### VSCode 断点调试建议

因为是双进程架构，直接 F5 调 TUI 主进程只能看到 TUI 那一侧；真正的 agent graph 在子进程里，需要用 `debugpy.listen()` + attach 才能断点跟进子进程。常见配置方向：

1. 跑/调 pytest 单测（最简单，最实用）
2. 跑 `deepagents-code` CLI 主入口（Python module `deepagents_code.main`）
3. attach 到已运行的 `langgraph dev` 子进程（需要在子进程启动代码里注入 debugpy）
4. 调 examples 目录里的独立脚本

## 轮次 3 - VSCode 断点调试需要哪些插件

### 用户提问要点

- 想加断点调试
- 询问 VSCode 还需要装哪些插件

### 结论 / 方案

**必装（核心）**

| 插件 ID | 作用 | 项目推荐状态 |
|---|---|---|
| `ms-python.python` | Python 语言 + 调试入口 | ✅ 已在 `.vscode/extensions.json` |
| `ms-python.debugpy` | Python 调试后端（2024 年从主插件拆出） | ❌ 未推荐，建议补上 |

**强烈建议**

- `ms-python.vscode-pylance`：语言服务器，Debug 时看变量/悬浮类型/跳转定义都靠它

**可选**

- `ms-toolsai.jupyter`：如果要 cell 调试（`settings.json` 已启用 jupyter 相关配置）
- `usernamehw.errorlens`：错误内联显示，纯生活质量

**不建议装**

- `ms-python.mypy-type-checker`：本项目用 `ty`（Astral 出品的类型检查器），不用 mypy

### 检查命令

```bash
code --list-extensions | grep -E "python|debugpy|pylance"
```

或命令面板 → `Extensions: Show Installed Extensions`
