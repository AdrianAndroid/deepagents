# zjcode 品牌定制隔离层迁移方案

> 日期：2026-07-30
> 目标：彻底解决 main→learn 合并冲突问题，不丢上游改动，不丢品牌定制

---

## 🎯 问题诊断

### 当前品牌定制分布（2026-07-30 快照）

| 文件 | 品牌定制内容 | 冲突风险 |
|------|-------------|----------|
| `_constants.py` | `CONFIG_DOTDIR=".zjcode"`, `PROJECT_DOTDIR=".zjcode"` | ⚠️ 高 |
| `_version.py` | `DISTRIBUTION_NAME="zjcode"`, `BRAND_NAME="zjcode"`, `PYPI_URL` | ⚠️ 高 |
| `_env_vars.py` | `NO_MOUSE`, `PYPI_URL`, `SDK_PYPI_URL` | ⚠️ 高 |
| `config.py` | 多处硬编码 `.zjcode` 路径 | ⚠️ 高 |
| `update_check.py` | 大量使用 `DISTRIBUTION_NAME` | ⚠️ 高 |
| `mcp_trust.py` | 整个文件（上游删除） | 🔴 极高 |
| `todo_list_prompt.md` | 整个文件（上游删除） | 🔴 极高 |
| `main.py` | `DISTRIBUTION_NAME` 引用, MCP 信任逻辑 | ⚠️ 高 |
| `model_config.py` | `DEFAULT_CONFIG_DIR = Path.home() / ".zjcode"` | ⚠️ 高 |
| `config_manifest.py` | `NO_MOUSE`, `PYPI_URL`, `SDK_PYPI_URL` | ⚠️ 高 |
| `mcp_tools.py` | `_mcp_trust_list_notices` | ⚠️ 高 |

| `subagents.py` | `.zjcode/agents/` 路径 | ⚠️ 中 |

### 核心问题

每次合并上游 main 分支时：
1. ✅ **我们的品牌定制经常被覆盖**（DISTRIBUTION_NAME 变回 deepagents-code）
2. ✅ **我们新增的文件被删除**（mcp_trust.py, todo_list_prompt.md）
3. ✅ **硬编码的 .zjcode 路径变回 .deepagents**
4. ❌ **同时可能丢失上游的 bug 修复和新功能**（如果用 merge=ours 策略）

---

## 🏗️ 解决方案：补丁层模式（Patch Layer Pattern）

### 架构图

```
┌─────────────────────────────────────────────────────────────┐
│                    UPSTREAM MAIN CODE                        │
│  libs/code/deepagents_code/*                                │
│  (完全不修改，100% 跟随上游，0 冲突)                         │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           │ import
                           ▼
┌─────────────────────────────────────────────────────────────┐
│               🎨 ZJCODE BRAND PATCH LAYER                     │
│  libs/code/zjcode/                                          │
│  (100% 我们的代码，上游永远没有这个目录，0 冲突)              │
│                                                             │
│  ├── brand.py              # 品牌常量定义                   │
│  ├── patches.py            # 运行时补丁应用器               │
│  ├── mcp_trust.py          # MCP 信任模块 (从 deepagents_code 移动)
│  └── todo_list_prompt.md   # Todo 提示模板 (移动)           │
└─────────────────────────────────────────────────────────────┘
```

### 核心原则

1. **零修改原则**：`deepagents_code/` 下的文件我们**一行都不修改**（除了 3 行导入钩子）
2. **集中原则**：所有品牌定制 100% 集中在 `zjcode/` 目录
3. **运行时补丁**：通过 Python 动态赋值覆盖常量，不修改源码

#### 1.3 `zjcode/patches.py` 内容

```python
"""
运行时品牌补丁应用器

原理：在 Python 模块导入后，动态修改模块的属性
优点：
1. 完全不修改上游源码
2. 100% 接收上游的 bug 修复和新功能
3. 我们的定制永远生效
"""

import importlib
import logging
from typing import Any

from zjcode.brand import PATCH_MAP

logger = logging.getLogger(__name__)


def apply_brand_patches() -> None:
    """应用所有品牌定制补丁

    在应用启动早期调用，确保所有品牌定制在使用前生效。
    """
    applied_count = 0
    failed_count = 0

    for module_path, patches in PATCH_MAP.items():
        try:
            module = importlib.import_module(module_path)

            for name, value in patches.items():
                if hasattr(module, name):
                    old_value = getattr(module, name)
                    if old_value != value:
                        setattr(module, name, value)
                        applied_count += 1
                        logger.debug(
                            f"[zjcode] Patched {module_path}.{name}: "
                            f"{old_value!r} → {value!r}"
                        )
                else:
                    logger.warning(
                        f"[zjcode] Cannot patch {module_path}.{name}: "
                        f"attribute does not exist (upstream may have changed)"
                    )
                    failed_count += 1

        except ImportError:
            logger.warning(f"[zjcode] Module {module_path} not found, skipping patches")
            failed_count += len(patches)

    if applied_count > 0:
        logger.info(f"[zjcode] Applied {applied_count} brand patches")
    if failed_count > 0:
        logger.warning(f"[zjcode] Failed to apply {failed_count} brand patches")


def patch_path_constants() -> None:
    """修补硬编码的路径常量

    对那些在模块级别就计算好的路径，需要在使用前重新计算。
    """
    from pathlib import Path

    # 修补 config.py 中的路径
    try:
        from deepagents_code import config

        # 覆盖全局配置路径
        config._GLOBAL_DOTENV_PATH = Path.home() / ".zjcode" / ".env"

        # 修补 DEFAULT_CONFIG_DIR
        from deepagents_code import model_config

        model_config.DEFAULT_CONFIG_DIR = Path.home() / ".zjcode"

        logger.info("[zjcode] Patched path constants")
    except Exception as e:
        logger.warning(f"[zjcode] Failed to patch path constants: {e}")


def apply_all_patches() -> None:
    """应用所有补丁的入口函数"""
    apply_brand_patches()
    patch_path_constants()
```

## 🔍 合并后检查清单（迁移后）

创建 `scripts/check-brand-after-merge.sh`：

```bash
#!/bin/bash
# zjcode 品牌完整性检查脚本
# 每次合并 main 分支后运行

RED='\033[0;31m'
GREEN='\033[0;32m'
YELLOW='\033[1;33m'
NC='\033[0m' # No Color

echo -e "${YELLOW}🔍 检查 zjcode 品牌定制完整性...${NC}"
echo ""

ERRORS=0

# 检查 1: zjcode 目录存在
if [ ! -d "libs/code/zjcode" ]; then
    echo -e "${RED}❌ 严重: zjcode 目录不存在！${NC}"
    echo "   恢复命令: git checkout HEAD -- libs/code/zjcode/"
    ERRORS=$((ERRORS + 1))
else
    echo -e "${GREEN}✅ zjcode 目录存在${NC}"
fi

# 检查 2: 关键品牌文件
for file in "zjcode/brand.py" "zjcode/patches.py" "zjcode/mcp_trust.py" "zjcode/todo_list_prompt.md"; do
    if [ ! -f "libs/code/$file" ]; then
        echo -e "${RED}❌ 丢失: $file${NC}"
        ERRORS=$((ERRORS + 1))
    fi
done

# 检查 3: __init__.py 中的钩子
grep -q "zjcode" libs/code/deepagents_code/__init__.py
if [ $? -ne 0 ]; then
    echo -e "${YELLOW}⚠️  警告: __init__.py 中可能缺少 zjcode 钩子${NC}"
fi

# 检查 4: DISTRIBUTION_NAME 常量
grep -q 'DISTRIBUTION_NAME.*zjcode' libs/code/zjcode/brand.py
if [ $? -ne 0 ]; then
    echo -e "${RED}❌ DISTRIBUTION_NAME 不是 zjcode${NC}"
    ERRORS=$((ERRORS + 1))
fi

echo ""
if [ $ERRORS -eq 0 ]; then
    echo -e "${GREEN}✅ 所有品牌定制检查通过！${NC}"
    exit 0
else
    echo -e "${RED}❌ 发现 $ERRORS 个问题，请检查修复${NC}"
    exit 1
fi
```

## ⚠️ 注意事项和风险

### 风险 1：运行时补丁的时序问题

**问题**：某些模块在导入时就计算了常量，补丁打晚了。

**解决方案**：
- 确保 `__init__.py` 的钩子在**最顶部**
- 对于在模块级别计算的路径，在 `patches.py` 中专门处理

### 风险 2：上游重构导致补丁目标不存在

**问题**：上游重构了模块结构，我们要补丁的常量没了。

**解决方案**：
- `patches.py` 中有完善的异常处理和日志
- 每次合并后运行检查脚本
- 补丁失败会有警告，但不会导致程序崩溃

### 风险 3：调试困难

**问题**：常量被动态修改了，源码里看不到。

**解决方案**：
- 给补丁操作打上详细的 debug 日志
- 在 `brand.py` 中集中定义所有补丁映射
- 文档化：所有品牌定制都在一个地方
