### 轮次 1 - install.sh / install.ps1 增加已安装检测,并部署到服务器

**用户提问要点**
- 修改 `web/` 下的安装脚本：如果本地已安装 `deepagents-code`，则更新到最新版本
- 改好后上传到服务器

**改动位置**
- `web/install.sh` 第 46-80 行左右（`--- 2. detect existing install and choose action ---` 段落）
- `web/install.ps1` 对应段落（PowerShell 版本）

**核心逻辑**
1. 通过 `uv tool list` 抓取已安装版本
   - bash 用 `awk '$1==pkg{print $2}'`
   - PowerShell 用 `-split '\s+', 2` 解析每行
2. 根据是否已安装 + 是否指定 `PKG_VERSION`，打印不同提示：
   - 已装 + 未指定版本 → `detected ... ; upgrading to latest...`
   - 已装 + 指定版本 → `detected ... ; reinstalling ...`
   - 未装 → `installing ... from ...`
3. 仍旧调用 `uv tool install <spec> --force`，因为 `--force` 既支持首装也会覆盖升级到最新版
4. 安装完成后再次 `uv tool list` 拿到新版本，输出：
   - `upgraded: X -> Y`
   - `already at X (no change)`
   - `installed: X`

**为什么这样做**
- `uv tool` 没有独立的 `upgrade` 子命令与 `--force reinstall` 语义差异；用 `--force` 统一路径最稳
- `uv tool list` 输出格式为 `pkgname vX.Y.Z ...`，简单 split 就能拿版本号，避免额外依赖 `jq` 之类

**部署操作**
- `cd web && bash run-deploy.sh --dry-run` 确认只影响 `install.sh` / `install.ps1`
- `bash run-deploy.sh` 执行真实同步：`root@8.152.204.58:/opt/1panel/www/sites/8.152.204.58/index/`
- `curl -fsS http://8.152.204.58:40080/install.sh | grep detect` 校验远端已生效

### 轮次 2 - 修 bug: 脚本装成了线上版本而不是私有源版本

**用户反馈**
- 执行安装脚本后，装到的是公共 PyPI 上的 `deepagents-code`，不是私有源里的构建

**根因分析**
- 脚本用了 `uv tool install ... --index-strategy unsafe-best-match`
- 该策略会跨所有 index 挑"版本号最高"的候选
- `deepagents-code` 是 langchain-ai 官方包，公共 PyPI 上是 `0.1.34`，私有源里只有 `0.0.3`
- `0.1.34 > 0.0.3` → uv 必选公共版

**校验方式**
```bash
curl -fsS https://pypi.org/pypi/deepagents-code/json | jq -r .info.version
# -> 0.1.34
curl -fsS http://admin:admin@8.152.204.58:48080/simple/deepagents-code/ | grep -oE 'deepagents[_-]code-[0-9.]+' | sort -u | tail
# -> 最高 0.0.3
```

**修复方案**
- 从 `install.sh` / `install.ps1` 移除 `--index-strategy unsafe-best-match`
- 回到 uv 默认策略 `first-index`：命中第一个含该包的 index 就停
- `--index-url` 指向私有源 → `deepagents-code` 强制走私有源
- `--extra-index-url` 指向公共 PyPI → 仅用于解决传递依赖（LangChain 等）
- 在脚本里加了注释块说明这个坑，避免以后又被"手抖加回来"

**部署**
- `bash run-deploy.sh` rsync 到 `root@8.152.204.58:/opt/1panel/www/sites/8.152.204.58/index/`
- `curl http://8.152.204.58:40080/install.sh | grep index-strategy` 校验远端已无该 flag

**建议后续动作**
- 在实际用户机器上跑一次 `curl ... | bash`，`uv tool list | grep deepagents-code` 确认版本是 `0.0.3` 而不是 `0.1.34`
- 如果要覆盖公共版更新到 `0.1.x`，需要在私有源里发布对应版本号的包，或考虑给包改名（避免与官方冲突）

### 轮次 4 - 真正的根因: 必须精确 pin 版本 + unsafe-best-match + allow-prerelease

**用户反馈**
- 按上一轮修复后跑 `curl ... | install.sh | bash`，Ubuntu 上仍旧装到 `deepagents-code==0.1.22`（公共 PyPI 版本），不是私有源的 0.0.3
- 说明"只删 `--index-strategy unsafe-best-match`"根本没解决问题

**取证**
```bash
# 远端 install.sh 已经没有 unsafe-best-match 了(上一轮修复的确生效)
curl -fsSL http://8.152.204.58:40080/install.sh | sed -n '60,85p'
# 私有源里 deepagents-code 最高确实是 0.0.3
curl -fsS http://admin:admin@8.152.204.58:48080/simple/deepagents-code/ | grep -oE 'deepagents[_-]code-[0-9.]+' | sort -u
```

**真正的根因**
- 公共 PyPI 上 langchain-ai 也发布了同名包 `deepagents-code`(langchain-ai 官方产物,当前 0.1.x)
- uv 默认 `first-index` 策略：一旦在任何 index 里找到这个包名就锁死那个 index,其他 index 不再查
- `--extra-index-url` 是隐含跟 `--index-url` 平级参与查找的,并非"只用于传递依赖"
- 结果:只传包名不带版本时,uv 优先命中公共 PyPI
- 上一轮的"删掉 unsafe-best-match"完全没解决问题(反而在下一步埋了新的坑)

**新坑发现**
- 直接 pin `==0.0.3` 但保持默认策略时,uv 报:
  `Because there is no version of deepagents-code==0.0.3 ...`
  hint 明确写:"A compatible version may be available on a subsequent index ...
  use --index-strategy unsafe-best-match to consider all versions from all indexes"
- 说明 uv 锁死公共 index 后连 0.0.3 都不会去私有源里找

- 再加 `--index-strategy unsafe-best-match` 后又报:
  `deepagents-code==0.0.3 depends on deepagents==0.7.0a3, pre-releases weren't enabled`
- 私有源的 0.0.3 依赖 `deepagents==0.7.0a3` (预发布),必须 `--prerelease=allow`

**最终正确组合(install.sh 现在这样)**
1. 脚本启动时 `curl` 私有源 `/simple/deepagents-code/`,正则提取所有 `X.Y.Z`,`sort -V | tail -1` 拿最高版本
2. 拼 `SPEC="deepagents-code==<那个版本>"` (公共 PyPI 上没有 0.0.x,天然不会串)
3. `uv tool install "$SPEC" --index-url PRIV --extra-index-url PUB --index-strategy unsafe-best-match --prerelease=allow --force`
4. 安装后 safety check:`uv tool list` 里 `deepagents-code` 版本必须匹配 `^v?0\.0\.`,否则报错退出
5. 私有源查询失败时直接 `die`,不静默回落公共 PyPI
6. PowerShell 版本同步全部改动

**关键教训**
- "safety" 不来自 `--index-strategy`,而来自 **精确 pin 一个只在私有源存在的版本号**
- 公共 PyPI 上如果存在同名包,uv 的 `first-index` 反而是"陷阱":会让你误以为在用私有源
- 有些坑得靠 uv 的 hint 消息读出来 —— 别嫌它长,里面就是修复配方
- 修复顺序:pin 版本 → 跨 index 搜 → 允许 prerelease,三个缺一不可

**诊断（用户在 Ubuntu 上执行手动清理时的现场数据）**
```
type -a dcode           # -> /home/zhaojian/.local/bin/dcode
uv tool uninstall ...   # 无输出（没装在 uv tool 里）
pipx uninstall ...      # 无输出（没装在 pipx 里）
python3 -m pip uninstall -y deepagents-code            # 无输出
python3 -m pip uninstall -y --user deepagents-code     # 无输出
sudo python3 -m pip uninstall -y deepagents-code       # 输入密码后无输出
rm -f ~/.local/bin/dcode ...                            # 手动删 shim 后 command -v dcode 才空
```

**根因**
- `dcode` 位于 `~/.local/bin/`，是 conda `(base)` 环境下 `pip install --user` 装出来的
  entry-point（而不是 uv tool 管理的 shim）
- 旧脚本只覆盖 `uv tool uninstall` 单一路径，其它安装方式一概无法识别

**修复方案（新版 `uninstall.sh` / `uninstall.ps1`）**
广谱清理，覆盖所有已知安装通道：
1. `uv tool uninstall`
2. `pipx uninstall`
3. 遍历 PATH 上所有 `python*` 解释器：
   - `pip show deepagents-code` 探测是否装在该解释器的 site-packages
   - 命中就 `pip uninstall -y`（默认 scope 和 `--user` scope 各跑一次）
   - 这一步是覆盖 Ubuntu 上 `pip install --user` 场景的关键
4. 扫描候选 bin 目录（`~/.local/bin`、`~/.cargo/bin`、`/usr/local/bin`、`/opt/homebrew/bin`
   或 Windows 上 `%USERPROFILE%\.local\bin` / `AppData\Roaming\Python\...\Scripts`）：
   查找 `dcode` / `deepagents-code` / `deepagents` 三个可执行文件残留
   - 会先读文件头判断是否是本包的 shim（避免误删同名可执行文件）
   - 命中就 rm
5. 最后重跑 `command -v` 打印残留检查结果，明确告诉用户是否清干净
6. 支持 `DRY_RUN=1` 环境变量：只打印将要执行的命令，不实际动手

**兼容性注意事项**
- `command -v -a` 在 macOS bash 3.2 下不可用；改用 `type -a | awk '{print $NF}' | awk '!seen[$0]++'` 做同样的事
- Windows 端在 PowerShell 里通过 `Get-Command -All` 拿到所有匹配，然后按目录白名单过滤
